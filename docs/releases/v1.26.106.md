# PlicZip v1.26.106 — CLI compatibility and security fixes

## Русский

### CLI и совместимость

- CLI-парсер переведён с `clap` на `argh`, при этом восстановлена совместимость привычных вызовов: компактные короткие параметры (`-x9`), значения через равенство (`--option=value`, `-p=secret`), `-h` и `--version`.
- Исправлена обработка `--`, имён файлов, похожих на опции или `help`, и путей с не-UTF-8 байтами. Отсутствующие значения опций теперь дают ошибку вместо ошибочной интерпретации следующего аргумента; ошибки парсинга завершаются кодом 2.
- Команда добавления архива проверяет наличие входных путей до запроса пароля.
- Машиночитаемый вывод переведён с JSON на RON через `--ron`.

### Benchmark и настройки

- Benchmark больших файлов перенесён из Python-скрипта в Rust-бинарник. Для запуска теперь требуется `--input`; при отсутствии входа утилита завершается ошибкой и не создаёт пустой отчёт. Поддержаны значения опций через `=` и пути с не-UTF-8 байтами; отчёт сохраняется в RON.
- Настройки GUI сохраняются в `config.kdl`; обновлены структура и тесты конфигурации.
- Исправлено восстановление временных меток файлов с учётом поддерживаемой версии Rust.

### Безопасность и проверки

- Распаковка 7z выполняется через собственный проверяемый callback PlicZip: небезопасные пути вроде `../outside.txt` отклоняются до записи за пределы каталога. Добавлен тест, который создаёт вредоносный 7z-архив и проверяет отказ распаковки.
- CI запускает форматирование, аудит зависимостей, строгий Clippy и workspace-тесты на Linux, Windows и macOS; сохранены периодические fuzz smoke-тесты.
- `cargo audit --ignore RUSTSEC-2026-0245` завершается успешно. Исключение точечное: PlicZip не вызывает уязвимый стандартный API распаковки `sevenz-rust`, а собственная распаковка проверяет каждый путь. Сам advisory не исправлен upstream.
- Аудит также сообщает о шести неподдерживаемых crates без доступного исправления: `chrono`, `sevenz-rust`, `ttf-parser`, `zbus_names`, `zvariant` и `zvariant_derive`. Эти предупреждения остаются видимыми в CI.

## English

### CLI and compatibility

- The CLI parser migrated from `clap` to `argh` while restoring familiar invocation forms: compact short options (`-x9`), equals-style values (`--option=value`, `-p=secret`), `-h`, and `--version`.
- Fixed handling of `--`, filenames that look like options or `help`, and paths containing non-UTF-8 bytes. Missing option values now produce an error instead of consuming the next argument incorrectly; parser errors exit with code 2.
- The archive-add command now validates that input paths are present before prompting for a password.
- Machine-readable output moved from JSON to RON via `--ron`.

### Benchmark and settings

- The large-file benchmark moved from a Python script to a Rust binary. It now requires `--input`; without input it exits with an error and does not create an empty report. Equals-style option values and non-UTF-8 paths are supported; reports are written in RON.
- GUI settings are stored in `config.kdl`; the configuration structure and tests were updated.
- File timestamp restoration was adjusted to remain compatible with the project's supported Rust version.

### Security and checks

- 7z extraction uses PlicZip's own checked callback: unsafe paths such as `../outside.txt` are rejected before any write can escape the output directory. A regression test creates a malicious 7z archive and verifies that extraction fails.
- CI runs formatting, dependency auditing, strict Clippy, and workspace tests on Linux, Windows, and macOS; scheduled fuzz smoke tests remain enabled.
- `cargo audit --ignore RUSTSEC-2026-0245` passes. The exception is narrowly scoped: PlicZip does not call `sevenz-rust`'s vulnerable default extraction API, and its own extraction path validates every archive member. The upstream advisory remains unpatched.
- The audit also reports six unmaintained crates with no available fixes: `chrono`, `sevenz-rust`, `ttf-parser`, `zbus_names`, `zvariant`, and `zvariant_derive`. These warnings remain visible in CI.
