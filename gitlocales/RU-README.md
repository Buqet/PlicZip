# PlicZip

Архиватор с собственным форматом `.plz`: индекс в конце файла, сжатие deflate/brotli, BLAKE3 на каждый файл и блок, шифрование паролем, многотомные архивы, безопасная распаковка. Написан на Rust, без C-зависимостей.

```text
$ pliczip a backup.plz ./документы -x9
$ pliczip a секрет.plz ./документы --password=пароль --volume-size 700M
$ pliczip l backup.plz -l
$ pliczip t backup.plz
$ pliczip x backup.plz -o ./восстановлено
```

> Пути в примерах — заглушки, подставь свои каталоги. Если пути нет, PlicZip
> скажет прямо: `pliczip: ошибка: путь не найден: ".\фото"`.

## Сборка

```
cargo build --release
# CLI:  target\release\pliczip.exe (2.7 МБ)
# GUI:  target\release\pliczip-gui.exe (14.6 МБ)
```

Только чистый Rust: `flate2` (miniz_oxide), `brotli`, `chacha20poly1305`, `argon2` — без C-кода. Поэтому сборка не требует MSVC `cl.exe` и работает в путях с кириллицей. GUI — на egui/eframe, тоже без C-зависимостей.

## Команды

| Команда ↕▾ | Алиас ↕▾ | Что делает ↕▾ |
|---|---|---|
| −`add <архив> <пути...>` | `a` | упаковать файлы и каталоги |
| −`extract <архив>` | `x` | распаковать |
| −`list <архив>` | `l` | показать содержимое |
| −`test <архив>` | `t` | проверить целостность, ничего не записывая |
| −`info <архив>` | `i` | сведения об архиве |
⚙

### Упаковка

```
pliczip a backup.plz ./документы ./заметки     # свои каталоги, не заглушки
pliczip a -x9 backup.plz ./исходники           # максимум сжатия
pliczip a --solid backup.plz ./исходники       # склеивать мелкие файлы
pliczip a -x0 backup.plz ./видео               # без сжатия, просто контейнер
pliczip a -c "перед отпуском" backup.plz .     # с комментарием
pliczip a backup.plz src --exclude "**/*.tmp" --exclude "target"
pliczip a src.plz src --include "**/*.rs"      # только нужные файлы
```

Каталог попадает в архив вместе со своим именем: `a x.plz photos` даст внутри `photos/...`, как в 7-Zip.

### Степени сжатия

| Степень ↕▾ | Метод ↕▾ | Когда использовать ↕▾ |
|---|---|---|
| −`-x0` | без сжатия | уже сжатое (видео, jpg, другие архивы) |
| −`-x1..4` | deflate | быстро, умеренно |
| `-x5` (по умолчанию) | brotli q5 | разумный баланс |
| `-x9..11` | brotli q9..q11 | долго, но текст/код/логи жмёт заметно сильнее |
⚙

Если сжатие не уменьшило блок, он сам сохраняется как есть — архив не раздувается.

### Фильтры

`--exclude` и `--include` принимают маски, можно повторять:

- `*` — любые символы, кроме `/`;
- `?` — ровно один символ, кроме `/`;
- `**` — любые символы, включая `/`.

Исключение всегда сильнее включения. Исключённый каталог не обходится вообще: `--exclude target` на большом дереве экономит время, а не только место.

### Прогресс

Упаковка, распаковка и проверка показывают ход работы одной строкой в stderr:

```
 сжатие 812.4 MiB / 1.42 GiB  57%  186 MiB/s  осталось 4.3s
```

Скорость и остаток считаются по скользящему окну в пять секунд, а не по всему времени с начала: на смешанных данных среднее врёт в разы — первые секунды уходят на индексацию и мелкие файлы, а потом идут гигабайты. `-q` убирает прогресс.

## Защита паролем

```
pliczip a секрет.plz ./документы -p                  # спросит пароль дважды
pliczip a секрет.plz ./документы --password="длинный пароль"
pliczip x секрет.plz -o ./out --password="длинный пароль"
pliczip t секрет.plz            # спросит пароль интерактивно
```

- `-p` без значения спрашивает пароль интерактивно — он не попадает в историю
команд и в список процессов;
- `--password=…` только через знак равенства — иначе `-p backup.plz` съело бы
имя архива как пароль;
- `--password-file pw.txt` — пароль из первой строки файла;
- `PLICZIP_PASSWORD` — переменная окружения, удобна для скриптов.
- ключ выводится через **Argon2id** (64 МиБ, 3 прохода) из случайной соли;
- данные и имена файлов шифруются **ChaCha20-Poly1305** кусками по 1 МиБ;
- шифруется и индекс, поэтому список файлов тоже не виден без пароля;
- неверный пароль и порча архива неотличимы по сообщению — это не оракул;
- пароль не восстанавливается. Потеряли — потеряли архив.

Кусочность важна: файл на 20 ГБ шифруется и расшифровывается потоком, не занимая 20 ГБ памяти.

## Тома

```
pliczip a backup.plz ./фото --volume-size 700M   # получится backup.plz.001, backup.plz.002, …
pliczip x backup.plz -o ./out      # прочитает все тома подряд
```

Тома — обычная нарезка байт, формат внутри не меняется. Читателю не нужно знать размер тома: он склеивает файлы по порядку. Достаточно указать `.001` — остальное найдётся само.

Если потерять средний том, архив не распакуется: лучше явная ошибка, чем молча неполный результат.

## Распаковка

```
pliczip x backup.plz                     # в текущий каталог
pliczip x backup.plz -o ./восстановлено
pliczip x backup.plz --skip-existing     # не трогать уже существующие файлы
pliczip x backup.plz --no-verify         # без проверки хешей (быстрее)
```

По умолчанию контрольные суммы проверяются, и при несовпадении распаковка останавливается с ошибкой. Восстанавливаются время изменения файлов и unix-права (на Windows — флаг «только чтение»).

## Машинный вывод

`l`, `i` и `t` понимают `--json`:

```
pliczip l backup.plz --json
pliczip i backup.plz --json
pliczip t backup.plz --json     # {"ok": true, ...} или {"ok": false, "error": ...}
```

## Графическая оболочка

```
pliczip-gui                    # пустое окно
pliczip-gui backup.plz         # открыть архив (так работает двойной клик)
```

Окно на egui/eframe, отдельный бинарник в том же воркспейсе, общая с CLI библиотека.

```
┌───────────────────────────────────────────────────────────┐
│ Файл  Вид  Справка                                        │
├───────────────────────────────────────────────────────────┤
│ + Добавить │ Распаковать │ Проверить │ Изменить   [поиск] │
├──────────────────────────────────────────┬────────────────┤
│ ИМЯ        РАЗМЕР  В АРХИВЕ  МЕТОД  …    │ СВОДКА         │
│ data/                                  — │ Формат  PLZ2   │
│   docs/readme.md        1.6 KiB  28 B  brotli │ ОБЪЁМ     │
│   photo/IMG_0001.jpg    7.3 KiB  38 B  brotli │ До сжатия  │
│                                          │ Экономия 99%   │
│                                          │ ┌───────────┐  │
│                                          │ │✓ Целостность│ │
│                                          │ │ подтверждена│ │
│                                          │ └───────────┘  │
├──────────────────────────────────────────┴────────────────┤
│ Готово · 3 блока · brotli/store · обычный   8.9 KiB → 85 B │
└───────────────────────────────────────────────────────────┘
```

Что умеет:

- **открытие** — через меню, двойным кликом по `.plz` (путь аргументом) или
перетаскиванием в окно; зашифрованный архив спрашивает пароль;
- **таблица содержимого** — имена, размеры, доля в архиве, метод, дата;
поиск по имени;
- **сводка и плашка целостности** — зелёная «подтверждена», красная
«повреждена», серая «не проверено»: состояние видно всегда, а не по
факту отдельной команды;
- **создание архива** — перетаскивание файлов, ползунок «быстро / баланс /
максимум» с расшифровкой последствий, solid, пароль, размер тома,
комментарий;
- **распаковка** — выбор каталога, проверка хешей по умолчанию;
- **прогресс с честным прогнозом** — скорость и остаток считаются по
последним секундам, а не по среднему с начала;
- **настройки** — тема (тёмная/светлая) и акцент (латунь/сталь/зелёный)
сохраняются в `%APPDATA%/pliczip/config.json`.

Пока не сделано: изменение существующего архива (кнопка «Изменить»), ассоциация `.plz` с Проводником и контекстное меню — это следующий блок.

## Целостность

Четыре уровня, все на BLAKE3:

```
файл  ──hash──┐
              ├── блок ──hash──┐
другие файлы ─┘                ├── индекс ──hash──┐
                               ┘                  ├── футер
длина индекса ────────────────────────────────────┘
```

- **файл** — ловит порчу содержимого, даже если блок распаковался;
- **блок** — ловит порчу сжатого потока целиком;
- **индекс** — защищает список файлов: без него можно было бы выкинуть файлы из
архива, и он остался бы «валидным»;
- **сигнатура в начале и в конце** — ловит обрезанный файл сразу, до разбора.

В зашифрованном архиве добавляется тег AEAD на каждый кусок, а хеши блоков считаются по данным после расшифровки — то есть проверка работает и там.

`pliczip t` проверяет всё, не создавая ни одного файла. Код возврата `1` означает повреждение, `2` — прочие ошибки.

## Безопасность распаковки

| Атака ↕▾ | Защита ↕▾ |
|---|---|
| −`../../secret` (zip-slip) | политика путей: `..`, `.`, пустые сегменты запрещены в формате |
| −абсолютные пути `/etc/…`, `C:\…` | запрещены на уровне валидации индекса |
| −ADS на NTFS (`file.txt:hidden`) | символ `:` запрещён |
| зарезервированные имена (`CON`, `NUL`, `aux.txt`) | запрещены |
| `Report.txt` + `report.txt` | уникальность без учёта регистра |
| ссылка `docs -> /etc` и запись через неё | ссылки создаются последними, наружу не выпускаются |
| подложенный заранее каталог-ссылка | путь проверяется после разыменования родителя |
| «бомба» на гигабайты | объём записи ограничен индексом, плюс лимит степени сжатия |
⚙

Проверка путей выполняется дважды: при записи (чтобы не создать мусор) и при чтении (чтобы не распаковать чужой мусор).

## Замеры

126 МиБ смешанных данных (76 МиБ текста + 50 МиБ несжимаемых), эта машина, `--release`:

| Режим ↕▾ | Архив ↕▾ | От исходного ↕▾ | Скорость упаковки ↕▾ |
|---|---|---|---|
| −`-x1` deflate | 50.7 МиБ | 40.2 % | 227 МиБ/с |
| −`-x5` brotli | 50.0 МиБ | 39.6 % | 185 МиБ/с |
| −`-x9` brotli | 50.0 МиБ | 39.6 % | 58 МиБ/с |
⚙

2000 файлов по 8 КБ (33 МиБ) — здесь решает solid-режим:

| Режим ↕▾ | Архив ↕▾ | Сжатие ↕▾ | Время ↕▾ |
|---|---|---|---|
| −обычный `-x5` | 0.72 МиБ | 45× | 1.48 с |
| −`--solid -x5` | 0.32 МиБ | 101× | 0.45 с |
| `--solid -x9` | 0.32 МиБ | 103× | 1.99 с |
⚙

Распаковка — около 700 МиБ/с, проверка целостности — примерно на той же скорости.

Шифрование добавляет 16 байт на каждый мегабайт данных и около 0.5 с на вывод ключа из пароля (один раз на архив).

## Формат

Полная спецификация: [docs/format.md](https://docs/format.md).

```
"PLZ1" | блоки данных | индекс (CBOR) | длина индекса u64 | BLAKE3 индекса | "PLZ1"
"PLZE" | параметры KDF | блоки данных | индекс | футер            (зашифрованный)
```

Индекс в конце — как в 7z: позволяет писать архив потоком, не зная сжатых размеров заранее. Цена — для чтения нужен `seek`, поэтому по трубе архив пока не читается.

Читатель версии 2 открывает и архивы версии 1 — формат совместим назад.

## Дизайн

Айдентика и интерфейс: [`design/pliczip-design.html`](https://design/pliczip-design.html) — самодостаточный мокап (знак, палитра, типографика, CLI, главное окно, диалог создания, ошибки, идеи). Открывается в браузере, тема переключается кнопкой справа сверху или ссылкой `#light`.

Решения и обоснования — в [`docs/design.md`](https://docs/design.md), знак — [`design/mark.svg`](https://design/mark.svg), снимки — `design/preview*.png`.

Коротко о принципах: молния как метафора имени, латунь как единственный акцент, зелёный и красный зарезервированы под целостность, и постоянная плашка «Целостность подтверждена» в главном окне — потому что это единственное, чем PlicZip отличается от 7-Zip по существу.

## Чего пока нет

Честный список, чтобы не искать:

- **recovery record** — испорченный сектор не восстановить (в планах, это отличие
от 7z и zip);
- **дедупликации** — одинаковые файлы пока хранятся отдельно, хотя хеши для этого
уже есть;
- **чтения из stdin** — из-за индекса в конце;
- **не-UTF-8 имён** — путь, который нельзя представить как UTF-8, не архивируется;
- **изменения архива** — файлы нельзя добавить в готовый архив и нельзя удалить
(кнопка «Изменить» в GUI пока пустая);
- **интеграции с Проводником** — ассоциации `.plz` и контекстного меню ещё нет;
- **цифровой подписи** архива;
- **шифрования только имён** без шифрования данных — осознанно не делаем: это
создаёт ложное ощущение защиты.

## Устройство

```
src/
  format.rs    контейнер: сигнатуры, структуры индекса, футер, валидация
  crypto.rs    Argon2id, ChaCha20-Poly1305, потоковые шифратор и расшифровщик
  compress.rs  deflate/brotli, выбор метода, хеширующий читатель
  safety.rs    политика путей: нормализация, zip-slip, имена Windows
  glob.rs      маски --exclude / --include
  source.rs    источник байтов: один файл или набор томов
  writer.rs    обход ФС, планирование блоков, параллельное сжатие, тома
  reader.rs    открытие, список, распаковка, проверка целостности
  util.rs      размеры, прогресс с ETA, плюрализация, UTF-8 в консоли Windows
  main.rs      CLI на clap
gui/
  main.rs      точка входа, запуск окна
  app.rs       состояние: открытый архив, диалоги, фоновые операции
  views.rs     главное окно: меню, тулбар, таблица, сводка, статусбар
  dialogs.rs   создание, распаковка, пароль, ошибка, прогресс
  theme.rs     палитра из docs/design.md, акценты
  config.rs    настройки в JSON
  icon.rs      знак приложения, собирается кодом
  progress.rs  канал прогресса и оценка остатка времени
tests/
  cli.rs       сквозные тесты через реальные процессы
  security.rs  вручную собранные вредоносные архивы
docs/format.md спецификация
design/        айдентика и мокап интерфейса
legacy/        прототип формата YZ01, из которого вырос проект
```

Прогресс идёт через `ProgressSink`: библиотека сообщает о ходе работы, CLI печатает строку в stderr, GUI — заполняет полосу и считает остаток времени. Поэтому окно не блокируется на время упаковки.

Память ограничена: блоки до 32 МиБ собираются в памяти и сжимаются параллельно (rayon), всё что больше — сжимается потоком прямо в файл. То же и с шифрованием: куски по 1 МиБ. Архив на десятки гигабайт собирается и распаковывается, не занимая столько же памяти.
